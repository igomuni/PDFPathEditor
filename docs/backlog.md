1. 上から順に、状態が「未着手」で「要確認」のない課題を 1 つ選ぶ。依存する課題が終わっていないものは飛ばす。
2. `main` から課題専用のブランチを作る(例: `feat/A-01-object-list`)。**作業は別の作業ツリー(`git worktree`)で行う。** 利用者は元のフォルダで `pnpm dev` を動かしていることがあり、そこで編集すると、書きかけの状態が動いているアプリにそのまま反映されて画面が壊れる(2026-11-15 に実際に起きた)。別の作業ツリーでは、最初に `pnpm install` と、`resources/`・`samples/`・`out/projects/` の用意(元のフォルダを参照するか、必要なものをコピーする)が要る。
3. 実装する。`docs/design.md` §3 の決定事項と `CLAUDE.md` の方針に従う。
4. 確かめる。次の 3 つがそろって完了とする。
   - `pnpm build`(型チェック・単体テスト・ビルド)が通る
   - 追加したロジックに単体テストがある(純粋な関数に切り出してテストする)
   - 実アプリで操作して確かめる(`scripts/e2e/`。手順は `scripts/e2e/README.md`)。`pnpm e2e out/projects/daiichi-candidates` の通し確認も通す

6. 課題専用のブランチにコミットする。**`main` へのマージとプッシュは利用者の指示を待つ**(2026-11-15 決定)。
7. 次の課題へ進む。前の課題に依存する場合は、そのブランチから続ける。

## A: 構成と一覧

### A-01 オブジェクト一覧と表示/非表示の切り替え
**背景**: Path / Text / Image などの構成要素を一覧で見たい。Inkscape のように、レイヤーやオブジェクトを個別に表示/非表示にしたい。項目コードも一覧で確かめたい。
**決定事項**: `docs/design.md` §3-38(非表示は保存する・出力は変えない)、§3-39(左に一覧、右に編集)。

やること:
- モデル: オブジェクトに `visible: boolean` を足す(省略時は表示)。古い document.json は読み込み時に補う。
- コマンド: `setObjectsVisible(document, ids, visible)`(Undo 可)。レイヤーの表示切替は既存の `setLayerVisible`。
- キャンバス: 非表示のオブジェクトは描かず、クリック・範囲選択・「すべて選択」の対象にしない。非表示にしたオブジェクトは選択から外す。
- 左サイドバー(下段): 「レイヤー → オブジェクト」のツリー。
  - レイヤー行: 名前、件数、目のアイコン(表示切替)、鍵(ロックは表示だけ)、折りたたみ
  - オブジェクト行: 種別アイコン(Path / Text / Image)、内容(Text は文字列、Path は「横線 / 縦線 / 点線 / 記入欄 / Path」、Image はファイル名)、役割、項目コード、目のアイコン
  - 行のクリックで選択(Shift で追加)。キャンバスがその位置へ移動する(画面外のときだけ。拡大率は変えない)
  - キャンバスで選択したら、一覧の該当行までスクロールして強調する
  - 絞り込み: 種別(Path / Text / Image)、役割、項目コードの有無、文字列の検索。絞り込んだ結果をまとめて表示/非表示にできる
  - 1 レイヤー 1000 件程度あるので、表示している行だけ描く(仮想スクロール)
- 種別ごとの一括切り替え(「Path を全部隠す」など)は、絞り込み + まとめて非表示で実現する。
- 出力(PDF / SVG / JSON)と確認用データは `visible` を見ない(§3-38)。JSON 出力には `visible` を含めない。
- 既存の右パネルの「項目コード一覧」はそのまま残す。

完了条件:
- 一覧から任意のオブジェクト・レイヤーを非表示にでき、保存して開き直しても残る。Undo で戻る。
- 非表示のオブジェクトがあっても、出力の件数と差分の数値が変わらない(単体テストで確かめる)。
- 第一表(約 960 件)で一覧のスクロールと選択が引っかからない。

関連: `src/shared/model.ts`、`src/renderer/src/commands.ts`、`Canvas.tsx`、`App.tsx`、`src/main/export/layout.ts`

### A-02 プロジェクト構成 v2(複数 PDF・複数ページ)
**背景**: 1 つのプロジェクトで複数の PDF と、その中の複数のページを扱いたい。PDF を 1 つ読み込むと、対象ページごとに処理層(背景・候補・確定)ができる形にする。
**決定事項**: §3-37(目次 + ページごとのファイル)。

フォルダ構成(v2):
```
project/
  document.json            目次(version 2)。sources と pages の一覧だけを持つ
  source/<sourceId>/<元のファイル名>.pdf     元 PDF(読み取り専用)
  pages/<pageId>.json      そのページのレイヤーとオブジェクト
  assets/<pageId>/…        そのページの背景ラスターなど
  fonts/                   使用フォント
  exports/<pageId>/…       ページごとの出力・検証・確認用データ
```

やること:
- モデル(`src/shared/model.ts`):
  - `ProjectManifest { version: 2, createdAt, sources: SourceInfo[], pages: PageRef[] }`
  - `SourceInfo` に `id` を足す。`PageRef { id, sourceId, sourcePageNumber, mediaBox, file }`
  - `PageDocument { version: 2, id, sourceId, sourcePageNumber, mediaBox, layers }`(今の `Page` に当たる)
  - 画面側のドキュメントは「目次 + 読み込んだページ」。ページは開いたときに読む(全ページを一度に読まない)
- 移行: version 1 の document.json を開いたら、v2 の形に読み替える。保存したときに v2 の構成で書き、元の document.json は `document.v1.json` として残す。移行の関数は純粋にして単体テストを書く。
- main(`src/main/project.ts`): 読み込み・保存をページ単位にする。保存は変更のあったページと目次だけを書く(一時ファイルに書いてから置き換える今の方式を保つ)。アセットや出力のパスは `src/main/safe-paths.ts` で検証する。
- 取り込み: 既存のプロジェクトに PDF を追加できる。同じ PDF(SHA-256 が同じ)なら source を共有し、ページだけを足す。ページ指定は「2」「1-3,5」の形で複数指定できる。
- 画面(`store.ts`): 「今のページ」を持つ。コマンドはページ ID を指す。Undo 履歴はプロジェクト全体で 1 本とし、別のページの操作を Undo するときはそのページへ切り替える。
- 出力・検証・確認用データ・修正ファイル: ページごとに `exports/<pageId>/` へ出す。PDF 出力は「今のページ」と「全ページ(1 つの PDF)」を選べる。
- 最近使ったプロジェクト、未保存の確認は今の動きを保つ(未保存かどうかはページ単位で持つ)。

完了条件:
- v1 のプロジェクト(`out/projects/daiichi-final` のコピー)を開いて保存すると v2 になり、開き直して件数・項目コード・出力の数値が変わらない。
- 1 つのプロジェクトに、同じ PDF の 2 ページ以上と、別の PDF 1 つを取り込める。
- 1 ページだけ変更して保存したとき、他のページのファイルの更新日時が変わらない。

メモ: 影響が広いので、(1) モデルと移行、(2) main の読み書き、(3) 画面のページ切り替え(A-03)の順に分けてコミットする。
