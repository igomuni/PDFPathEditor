# PDFPathEditor 設計メモ v0(壁打ち結果)

作成日: 2026-11-15 / 状態: 方針確定前の叩き台。決定事項と未決事項を分けて記載。
このファイルがリポジトリ上の正。Claude Project の `claude/design-v0.md` は構想メモとして残す。

## 1. 目的
画像PDF(ページ全体が1枚のラスター画像のPDF)を、再編集可能な構造化データ(Path / Text / Image)に変換し、人間がズレを微調整できるElectronデスクトップツールを作る。最終的に編集結果からPDFを生成する。

## 2. 用語
- ラスター: ピクセル(点)の集まりで表した画像。スキャン、写真、画像PDFのページ。拡大するとギザギザになる。
- ベクター: 線や曲線を座標と数式で表した図形。Path(パス)はその単位。拡大しても劣化せず、点を動かして編集できる。
- ベクタライズ(Path化): ラスターからベクターを作ること。
- 画像PDF: ページ全体が1枚のラスターで、文字も罫線も選択・編集できないPDF。

## 3. 決定事項
1. 元PDFは直接編集しない。背景レイヤー(読み取り専用)としてプロジェクトで管理し、出力PDFとは分離する。
2. 最終成果物は第一表のPDF。あわせて Path / Text / Image / その他の構成要素を二次利用しやすいデータとして保持する。
3. 画像PDFを再編集可能な形式にすることが中核機能。
4. Text は実フォントのTextオブジェクトにする(フォントの変更・サイズ変更を編集対象に含める)。
5. 項目コード(G01 等)を各オブジェクトにタグ付けする(PoCに含める)。
6. UI は React + SVG キャンバス(ズーム/パンは viewBox 操作)。
7. Path化の方式(Potrace / VTracer / 独自の線分検出 など)は未定。差し替え可能なインターフェースにしておく。
8. 背景ラスターの生成は pdfjs-dist + @napi-rs/canvas(main 側の utility process)で行う。ページ全体を指定dpiで描画する(小片画像・クリップパス込み)。(2026-11-15 決定)
9. 暗号化(変更不可)の元PDFは、無変更で `source/` にコピーして読み取り専用にし、SHA-256・暗号化の有無・権限フラグを `document.json` に記録する。ラスター抽出のみ行い、復号済みPDFは保存しない。(2026-11-15 決定)
10. ビルドは electron-vite、パッケージマネージャは pnpm。(2026-11-15 決定)
11. 取り込みはダイアログでPDFとプロジェクトフォルダの作成先を選ぶ。既定値は2ページ目・300dpi。(2026-11-15 決定)

## 4. PoC 対象
- 国税庁「令和8年分の所得税等の確定申告書(案)」PDF(0026006-063.pdf)の第一表(2ページ目)。
- 取得元: https://www.nta.go.jp/taxes/shiraberu/shinkoku/pdf/0026006-063.pdf
- 実態: 全32ページが画像PDF。2ページ目は 2481×3508px(300dpi, A4)のインデックスカラー画像1枚が主体で、クリップパス付きの小片画像が8枚重なる。テキスト層なし。
- 注意: 暗号化(AES)で「変更不可」の権限設定。パスワードなしで開ける。背景ラスター抽出のみで使う前提なので、元PDFは書き換えない。
- 注意: 様式は「案」で、今後変更される可能性がある。
- 第一表の要素: 罫線・枠、項目名ラベル(日本語)、数字マス・点線、項目コード(G01等の小さな印字)、QRコード、様式ID。

## 5. アーキテクチャ
### 5.1 プロジェクトの構成(フォルダ形式)
```
project/
  source/        元PDF(読み取り専用。ハッシュで同一性確認)
  assets/        抽出したラスター、QR等のImage
  fonts/         使用フォント(埋め込み用)
  document.json  レイヤー・オブジェクト(唯一の正)
  exports/       PDF / SVG / JSON
```

### 5.2 ドキュメントモデル
ページごとにレイヤーとオブジェクトを持つ。オブジェクトは共通属性(安定ID、種別、変換行列、Z順、タグ、メタデータ)を持つ。
- Path: 頂点列(ベジェ含む)、塗り、線色、線幅、閉/開
- Text: 文字列、フォント、サイズ、字間、色、配置、任意で「輪郭Pathで描画」フラグ
- Image: アセット参照、変換
- 役割(role): 枠 / ラベル / 記入マス / QR / 様式ID など
- 項目コード(fieldCode): 例 G01。二次利用(データ流し込み、AcroForm化)の鍵になる

レイヤー構成:
1. 背景ラスター(ロック)
2. 自動抽出の候補(未確定)
3. 確定オブジェクト(出力対象)
4. 差分オーバーレイ(確認用)

自動抽出は「候補を出すだけ」にして、人が確定した時点でレイヤー3に入る。精度が低くても使える設計にする。

### 5.3 パイプライン
取り込み(背景ラスター抽出) → 候補抽出(Vectorizer / OCR) → 人手調整 → 確定 → 出力(PDF / SVG / JSON) → 自動検証

自動検証: 出力PDFをラスタライズして背景との差分を計算し、PoCの成功基準を数値化する。

### 5.4 Electron 構成
- main: ファイルI/O、PDF抽出・出力、重い処理(ベクタライズ、OCR)を utility process で実行
- renderer: React + SVG。ドキュメントモデルを正とし、保存時にmainへ渡す
- 座標系: 内部はPDF座標(ポイント、左下原点)のまま保持し、SVG座標への変換レイヤーを1枚挟む
- Undo/Redo(コマンドパターン)は最初から入れる
- 参考: Inkscape(ビューと操作感)、stablyai/orca(Electron構成)

## 6. Text の方針
- 実フォントのTextとして出力する(コピー・検索・再利用可能)。
- 文字内容は人が確定する。OCR(Tesseract、macOS Vision 等)は候補提示のみ。
- 元フォントは Meiryo(サブセット埋め込み。画像PDFなので実際には画像化されている)で、再配布できない。出力は Noto Sans JP 等の再配布可能なフォントで近似し、PDFに埋め込む。
- 編集機能: フォントファミリ変更、サイズ変更、位置、字間。見た目の再現用に「輪郭Pathで描画」への切替も用意する。
- 出力側は pdf-lib + fontkit 等で日本語フォント埋め込みを検証する(要PoC)。

## 7. PoC スコープ(案)
1. 第一表(2ページ目)を300dpiで背景ラスターとして取り込む
2. 罫線・枠を検出して Path 候補にする(水平・垂直に正規化)
3. ラスター上に重ねて表示(不透明度、差分表示)。ノード・線分の選択とキー操作での微調整
4. ラベル文字を Text オブジェクト化(OCR候補 + 手動確定)、フォント・サイズ編集
5. 項目コードのタグ付け
6. PDF / SVG / JSON 出力と、背景との自動差分検証

成功基準(初期): 差分が目視で気にならない。その後、画素差分率などで数値化する。
