# PDFPathEditor 設計メモ v0(壁打ち結果)

作成日: 2026-11-15 / 状態: 方針確定前の叩き台。決定事項と未決事項を分けて記載。
このファイルがリポジトリ上の正。Claude Project の `claude/design-v0.md` は構想メモとして残す。

## 1. 目的
画像PDF(ページ全体が1枚のラスター画像のPDF)を、再編集可能な構造化データ(Path / Text / Image)に変換し、人間がズレを微調整できるElectronデスクトップツールを作る。最終的に編集結果からPDFを生成する。

## 2. 用語
- ラスター: ピクセル(点)の集まりで表した画像。スキャン、写真、画像PDFのページ。拡大するとギザギザになる。
- ベクター: 線や曲線を座標と数式で表した図形。Path(パス)はその単位。拡大しても劣化せず、点を動かして編集できる。
- ベクタライズ(Path化): ラスターからベクターを作ること。
- 画像PDF: ページ全体が1枚のラスターで、文字も罫線も選択・編集できないPDF。

## 3. 決定事項
1. 元PDFは直接編集しない。背景レイヤー(読み取り専用)としてプロジェクトで管理し、出力PDFとは分離する。
2. 最終成果物は第一表のPDF。あわせて Path / Text / Image / その他の構成要素を二次利用しやすいデータとして保持する。
3. 画像PDFを再編集可能な形式にすることが中核機能。
4. Text は実フォントのTextオブジェクトにする(フォントの変更・サイズ変更を編集対象に含める)。
5. 項目コード(G01 等)を各オブジェクトにタグ付けする(PoCに含める)。
6. UI は React + SVG キャンバス(ズーム/パンは viewBox 操作)。
7. Path化の方式(Potrace / VTracer / 独自の線分検出 など)は未定。差し替え可能なインターフェースにしておく。
8. 背景ラスターの生成は pdfjs-dist + @napi-rs/canvas(main 側の utility process)で行う。ページ全体を指定dpiで描画する(小片画像・クリップパス込み)。(2026-11-15 決定)
9. 暗号化(変更不可)の元PDFは、無変更で `source/` にコピーして読み取り専用にし、SHA-256・暗号化の有無・権限フラグを `document.json` に記録する。ラスター抽出のみ行い、復号済みPDFは保存しない。(2026-11-15 決定)
10. ビルドは electron-vite、パッケージマネージャは pnpm。(2026-11-15 決定)
11. 取り込みはダイアログでPDFとプロジェクトフォルダの作成先を選ぶ。既定値は2ページ目・300dpi。(2026-11-15 決定)
12. 罫線・枠のPath化は独自の線分検出で行う(二値化した画素の水平・垂直の連なりを線分にまとめる)。`Vectorizer` インターフェース(`src/shared/vectorizer.ts`)の実装の1つとして登録し、差し替え可能にする。文字のPath化方式は未決(§8)。(2026-11-15 決定)
13. 罫線は「2頂点の開いたPath + 線幅」(中心線表現)で持つ。交差する線は別々の線分のまま持つ。(2026-11-15 決定)
14. 点線は、同一直線上に等間隔で並ぶ点を1本のPathにまとめ、破線パターン(dash)を属性として持たせる。(2026-11-15 決定)
15. 目視用の差分表示は2色重ねにする。背景を赤、Pathをシアンで乗算合成し、一致=黒 / 背景のみ=赤 / Pathのみ=シアンで見せる。表示モードであり、ドキュメントには保存しない。数値による自動検証の指標は未決(§8)。(2026-11-15 決定)
16. 確定操作は、選択した候補を Enter で確定レイヤーへ移す方式と、候補の全件確定の両方を用意する。不要な候補は Delete で削除する。候補のままでも微調整できる。(2026-11-15 決定)
17. 矢印キーの移動量は背景ラスターの1画素(300dpi なら 0.24pt)。Shift で10倍、Alt で 1/10。(2026-11-15 決定)
18. 水平・垂直の罫線は、端点を動かしても向きを保つ。端点は線に沿う方向にだけ動き、直交方向の移動は線全体の平行移動になる。(2026-11-15 決定)
19. OCR は macOS Vision と tesseract.js の両方を実装し、画面で切り替える。エンジン共通の後処理(罫線位置での行の分割、均等割り付けの空白の除去、フォントに合わせたサイズ・位置・字間の推定)を通す。tesseract.js は罫線を文字として読むため、検出済みの罫線を消した画像を渡す。(2026-11-15 決定)
20. フォントは当面 Noto Sans JP と Noto Serif JP(SIL OFL)を使う。Windows での利用も想定しており、将来は MS ゴシック・MS 明朝を使えるようにしたい(再配布できないため、OS やプロジェクトの `fonts/` から読む形を想定)。Text はフォントを family と weight で指し、一覧は `src/shared/fonts.ts` で管理する。(2026-11-15 決定)
21. フォントファイルはリポジトリに含めず、`pnpm fonts` で配布元から `resources/fonts/` に取得する。保存時に、使っているフォントをプロジェクトの `fonts/` へコピーする。(2026-11-15 決定)
22. OCR の結果は、認識された行ごとに1つの Text オブジェクトにする。均等割り付けの項目名は字間(letterSpacing)で幅を合わせる。(2026-11-15 決定)
23. 項目コードの付与は半自動にする。「項目コードを割り当て」で印字コードを見つけて自動で付け、人がパネルで修正・解除・手入力する。すでに付いている項目コードは自動では上書きしない。(2026-11-15 決定)
24. 第一表では、印字コードは「コードだけが入った小さな枠」にあり、記入欄はその右隣の枠にある。自動で付ける範囲は、印字コードの Text と、右隣の枠(記入欄)の中のオブジェクトまでとする。項目名ラベルは対応が曖昧(「給与」が G16 と G44 の両方にかかる等)なので自動では付けず、手動にする。(2026-11-15 決定)
25. 記入欄の範囲は、線も塗りもない閉じた Path(role=inputCell、fieldCode 付き)として持つ。出力PDFには描かれないが、JSON から記入位置を引ける。割り当て時に、右隣の枠の内側に自動で作る。(2026-11-15 決定)
26. 印字された項目コードの Text には role=fieldCode を付け、項目名ラベル(label)と区別する。role はパネルで手動変更できる。(2026-11-15 決定)
27. 項目コードの表示は選択連動にする。選択したオブジェクトと同じ fieldCode を持つオブジェクトを強調し、パネルにコード一覧を出す。付け漏れ確認用に「未付与を強調」(テキストと記入欄が対象。罫線は隣の項目と共有するので対象外)を切り替えられる。表示モードであり、ドキュメントには保存しない。(2026-11-15 決定)
28. 出力PDFは PDFKit で生成する(main 側の utility process)。日本語フォントは使った文字だけをサブセットして埋め込む。当初案の pdf-lib + fontkit は、OTF(CFF)の Noto Sans JP をサブセット埋め込みすると文字化けし、全体埋め込みでは1フォントあたり約4MB増えるため採らない。(2026-11-15 決定)
29. 自動差分検証は、出力PDFを背景と同じ解像度でラスタライズし、二値化(濃度 128 未満をインク)して背景ラスターと比べる。1画素のずれは許す。指標は、再現率(背景のインクのうち出力に対応があるもの)、過剰率(出力のインクのうち背景に対応がないもの)、不一致画素率(対応のないインクが全画素に占める割合)の3つ。差分画像(一致=黒 / 欠落=赤 / 過剰=シアン)と数値を `exports/` に出す。合否の閾値は実測値を見てから決める(§8)。(2026-11-15 決定)
30. Text の「輪郭Pathで描画」は、フォントファイルのグリフ輪郭を取り出して、塗りつぶしのPathとして PDF / SVG に描く(fontkit)。背景の画像を輪郭トレースする方式(§8「文字のPath化の方式」)とは別。(2026-11-15 決定)
31. JSON 出力は document.json とは別の二次利用向けの形にする。確定オブジェクトの一覧(種別・role・fieldCode・外接矩形・各属性)と、項目コードごとの索引(記入欄の矩形、印字コード、関連オブジェクトのID)を持つ。背景・候補・レイヤーの表示状態は含めない。(2026-11-15 決定)
32. 出力先はプロジェクトの `exports/`。ファイル名は `output.pdf`、`page-NNNN.svg`(ページごと)、`output.json`、`verify-page-NNNN-diff.png`、`verify.json`。出力のたびに上書きする。SVG の Text はフォントを family 名で指し、フォントは埋め込まない。(2026-11-15 決定)
33. 候補の確認と修正は、アプリの外の AI(Claude Code など)に任せられるようにする。アプリは外部の AI を呼ばず、「確認用データの書き出し」と「修正ファイル(JSON)の取り込み」だけを持つ(API キーの管理や画像の外部送信をアプリに持ち込まない)。形式は `docs/corrections-format.md`。(2026-11-15 決定)
34. 修正ファイルの操作は、Text の置換・追加と、オブジェクトの削除。位置とサイズは、数値のほかに「文字のインクが収まる枠(fitBox)」でも指定でき、その場合はアプリがフォントの字形からサイズ・位置・字間を決める。(2026-11-15 決定)
35. 取り込みは、置換・追加・削除の件数と適用できない操作を表示して確かめてから、全件を1回の操作として適用する(Undo 1回で戻る)。適用できない操作はその操作だけ飛ばす。(2026-11-15 決定)
36. 確認用データでは、要確認箇所を機械的に洗い出す。(a) 罫線にも候補の Text にも対応しない背景のインクのまとまり、(b) 描いた文字のインクの 25% 超が背景に対応しない Text。背景に候補を重ねたタイル画像に番号付きの枠で示す。(2026-11-15 決定)
37. 1つのプロジェクトで複数のPDFと、その中の複数のページを扱う。PDFを取り込むと、対象ページごとに処理層(背景・候補・確定)ができる。保存は「目次 + ページごとのファイル」にする: `document.json` は取り込んだPDFと対象ページの一覧だけを持ち、レイヤーとオブジェクトは `pages/<ページID>.json` に持つ。変更したページだけを書く。既存(version 1)のプロジェクトは開いたときに読み替え、保存時に新しい構成にする。画面とIPCでは全ページを読み込んだ1つのドキュメントとして扱い、保存のときに、最後の保存から参照が変わったページだけを書く。Undo 履歴はプロジェクト全体で1本で、別のページの操作を戻すとそのページへ切り替わる。出力・検証・確認用データ・項目コードの割り当て・全件確定は「今のページ」を対象にする。(2026-11-15 決定)
38. オブジェクトごとの表示/非表示をドキュメントに保存する(Undo 可)。非表示のオブジェクトは画面に出さず、選択の対象にもしない。出力(PDF / SVG / JSON)には影響させない(確定オブジェクトは非表示でも出力する)。レイヤーの表示切替も同じ扱い。(2026-11-15 決定)
39. 画面は、左に一覧、右に編集とする。左サイドバーの上段に「PDF → ページ」のツリー、下段に「レイヤー → オブジェクト」のツリー(種別・内容・役割・項目コード・表示切替・絞り込み)。右パネルは選択したオブジェクトの編集用のまま。(2026-11-15 決定)
40. 残りの課題は `docs/backlog.md` にまとめ、Claude が自走で進める。課題ごとに専用ブランチで実装・確認・コミットまで行い、`main` へのマージとプッシュは利用者の指示を待つ。未決事項に当たった課題は飛ばし、質問を課題一覧に書き残す。(2026-11-15 決定)
41. 縦書きは、Text に組む向き(`writingMode`: 横書き / 縦書き。省略は横書き)を持たせて表す。「収入金額等」のような縦書きの見出しを、1つの Text として持つ。縦書きの Text の位置の基準は、1字目の仮想ボディ(全角の正方形)の上辺の中央。(2026-11-15 決定)
42. 縦書きは、文字を1字ずつ正立で上から下へ積み、左右の中央にそろえる。1字の送りは fontSize + 字間。括弧・長音・句読点はフォントの縦書き用の字形(OpenType の `vert`)に切り替える。半角の英数字も1字ずつ正立で積む。1つの Text は1列だけ(改行・複数列は別の Text にする)。計算は `src/shared/vertical.ts` にまとめ、画面・PDF・SVG・確認用データで同じものを使う。(2026-11-15 決定)
43. 「文字を検出」の後処理で、縦に並ぶ1字の Text を1つの縦書きの Text にまとめる。条件は、左右の中心がそろっている・サイズが近い・送りがそろっている・間に横の罫線がない、の4つ。対象はかな・漢字・括弧で、数字と記号(「ー」「・」を含む)はまとめない。縦書きを1行の大きな文字として読み違えたものは自動では直さない(修正ファイルとパネルで直す)。(2026-11-15 決定)
44. 「文字を検出」では、1回目の OCR のあとに「枠の読み直し」を行う。対象は、候補が背景と合っていない枠(描いたインクの 25% 超が背景に対応しない)と、読み落としのある枠。枠の中のインクを縦の列か横の行に分け、列・行ごとに読み直す。縦の列は、字を1字ずつ切り出して横1行に並べ直した画像にして読む(OCR は縦書きを読めないため)。読み直した結果は、置き換える元の候補より背景に合うときだけ採用する。(2026-11-15 決定)
45. 丸囲みの文字は、①〜㊿ と丸囲みのカタカナ(㋐ など)を1つの Text として持つ。51 以上の丸数字は Unicode に文字がないので、「数字の Text + 丸の Path」で持つ(丸は4本のベジェ曲線の閉じた Path。両方の meta.circled に数を入れる)。「文字を検出」で、丸(輪)を画像から直接探し、輪の中だけを読んで作る。輪に重なっていた1回目の候補(丸を外して読んだ数字など)は入れ替える。(2026-11-15 決定)
46. 文字の大きさが大きすぎる候補への対策は3つ。(a) 枠の読み直し(§3-44)で、複数の行や列を1行として読んだものを作り直す。(b) 丸囲みの文字は輪の大きさから決め直す(§3-45)。(c) それでも文字の高さが囲んでいる枠の高さを超える候補は、枠の中のインクだけでサイズと位置を決め直す。(2026-11-15 決定)
47. 「文字を検出」の最後に「読み落としの拾い直し」を行う。どの候補にも対応しない小さなインクのまとまり(1字、記号)を1つずつ切り出し、格子に並べた画像にして読む。横棒(記入欄の区切りの「ー」)は OCR が読まないので、形(横長で塗りつぶし)で決める。読んだ字は、かな・漢字・数字と様式に出てくる記号だけを受け付け、描いたときに元のインクと重なり、大きさがページのふつうの文字に近いものだけを採用する。(2026-11-16 決定)
48. 丸数字を「・」「〜」でつないだ並び(⑰・⑱ など)は、丸数字を1つずつの Text、つなぎの記号を別の Text として持つ。1回目の OCR が1行として読んだ候補(「①7-18」など)は、幅の半分以上が輪に重なっていれば外し、つなぎの記号は読み落としの拾い直しで拾う。(2026-11-16 決定)
49. 任意のテキストは「テキストを追加」で、表示している範囲の中央に候補として追加する(文字列・大きさ・位置は、パネルと矢印キーで直す)。選択したオブジェクトは「複製」で同じレイヤーに複製でき、「削除」で消せる。どれも Undo できる。ツールを切り替えて置く方式(Inkscape 風)は採らず、ボタン1つで足す簡単な方式にした。(2026-11-16 決定)
50. 選択したオブジェクトは、マウスのドラッグで動かせる。選択していないものをつかむと、それだけを選択して動かす。Shift を押している間は、動きの大きいほうの軸(水平または垂直)に固定する。頂点のドラッグは §3-18 に従う。ドラッグ 1 回は 1 つの履歴にする。Shift + クリックは選択の足し引きだけで、ドラッグは始めない。(2026-11-16 決定)
51. Text の文字列は、キャンバスの上で直接編集できる(ダブルクリック、F2、右パネルの「その場で編集」)。Enter またはフォーカスを外すと確定、Esc で取り消し、空にするとその Text を消す。編集中に、カーソルの位置、または選択した範囲で Text を分けられる(「選択範囲で分離」、⌘Enter)。「1字ずつに分離」「結合」もある。分離・結合では字の位置を変えない。分けた Text は左揃え(縦書きは上揃え)になり、1 つ目が元の ID を引き継ぐ。結合は、読む順(横書きは上の行から・左から、縦書きは右の列から・上から)に並べ、フォント・役割・項目コードは先頭のものを引き継ぐ。1 行(1 列)に並んでいれば、全体の幅(高さ)が変わらないよう字間を決める。(2026-11-16 決定)
52. キャンバスの右クリックで、選択に対する操作のメニューを出す(文字列を編集、結合、1字ずつに分離、縦書き/横書き、確定レイヤーへ移す、複製、削除、非表示、役割、項目コードを外す)。選択していないものの上で右クリックすると、それを選択してから出す。何もない場所では「テキストをここに追加」と表示の操作だけを出す。メニューは画面の中に描く(OS のメニューは使わない。自動確認で操作できるようにするため)。(2026-11-16 決定)
53. 左パネルは「ページ / オブジェクト / 項目コード」のタブ切り替えにする。一覧はすべて左、右パネルは選択したものの編集だけにする。項目コードの一覧は、コードごとに印字・記入欄の有無と件数を出し、行を押すとそのコードのオブジェクトを選択して表示位置を合わせる。印字か記入欄が欠けているコードだけに絞れる。項目コードが付いていない Text・記入欄の数を出し、まとめて選択できる。(2026-11-16 決定)
54. QRコードは Image として持つ(role=qr)。「QR・様式ID」で、背景ラスターから 3 隅の切り出しシンボル(黒:白:黒:白:黒 = 1:1:3:1:1)を探して QR の範囲を決め、その範囲の画素をそのまま切り出す(中身は読まない。作り直さない)。見つからないときのために、「画像を切り出す」でドラッグした範囲を Image として切り出せる。切り出した PNG は背景と同じフォルダ(`assets/<ページ>/`)に置く。様式ID は Text(role=formId)として持つ。「様式ID」という見出しの右隣にある英数字の Text に、同じボタンで役割を付ける。確定した Image は、PDF・SVG に PNG のまま埋め込む。(2026-11-16 決定)
55. 矢印(吹き出しから伸びる細い線 + 先端の塗りつぶした三角形)は、「罫線を検出」で一緒に検出し、軸を折れ線の Path、先端を塗りだけの閉じた Path(3 頂点)として持つ(どちらも role=other、`meta.source = 'arrow-detect'`)。細い線を消して残った塗りの形から三角形を選び、その底辺から細い線を曲がり角も含めてたどる。軸のない三角形は矢印にしない(記号の ▲ などを拾わないため)。軸と重なる罫線の候補は外す。(2026-11-16 決定)
56. 星(★)は Text として持つ。OCR は読まず、ふつうの字より大きく印字されるので、読み落としの拾い直しの中で形(ほぼ正方形で、3 割ほどが塗られたインクのまとまり)から候補にし、「★」を描いて元のインクと重なるときだけ採用する(重なり 90% 以上、はみ出し 20% 以下。ふつうの字より厳しくする)。大きさの制限(§3-47)は星には掛けない。(2026-11-16 決定)
57. PDF の中で回転しているページ(/Rotate 90・270。横長の帳票)は、表示される向きのページとして扱う。ページの大きさ(mediaBox)は表示される向きの幅・高さにし、モデルの座標は表示される向きの左下を原点にする。出力 PDF は回転を使わず、その向きのページとして作る。(2026-11-16 決定。それまでは縦長のページとして扱い、右側が出力と検証から外れていた)
58. 文字の大きさが大きすぎる候補への対策の 4 つ目(§3-46 の続き)。枠の読み直しの後でも、ページの文字の大きさの中央値の 2 倍を超え、描いたインクの半分以上が背景に対応しない候補は捨てる(OCR が複数の行や列を 1 行として読んだもので、文字列も当てにならない)。捨てた場所のインクは、読み落としの拾い直しと「取れていないインク」の対象になる。表題のような本当に大きい文字は、背景と合うので残る。(2026-11-16 決定)
59. 「罫線を検出」で、セルの斜線と角丸の枠の角も検出する。水平・垂直の罫線を消した残りのインクから細いまとまりを取り出し、直線に当てはまる長いもの(45 画素以上、水平・垂直から約 6 度以上傾いたもの)を斜線に、罫線の端 2 つにつながる 4 分の 1 の円弧を角丸の角にする。途中の罫線で切れた斜線は 1 本につなぐ。斜線は 2 頂点の Path、角は制御点付きの 2 頂点の Path で、どちらも罫線(role=frame)として持つ。点線の斜線は対象にしない。(2026-11-16 決定)

## 5. アーキテクチャ
### 5.1 プロジェクトの構成(フォルダ形式)
```
project/
  document.json                 目次(version 2)。取り込んだPDFと対象ページの一覧
  pages/<ページID>.json          そのページのレイヤー・オブジェクト(目次と合わせて唯一の正)
  source/<ソースID>/<ファイル名>  元PDF(読み取り専用。ハッシュで同一性確認)
  assets/<ページID>/             そのページの背景ラスターなど
  fonts/                        使用フォント(埋め込み用)
  exports/<ページID>/            そのページの PDF / SVG / JSON、検証結果、確認用データ(review/)
```
1つのプロジェクトに複数のPDF、PDFごとに複数のページを取り込める(§3-37)。ページIDは `page-0002-3f9a1c2e`(ページ番号 + 乱数)。
version 1(1つのPDF・1ページ、`document.json` に全部入り)のプロジェクトは、開いたときに読み替え、最初の保存で上の構成にする。
そのとき元の `document.json` は `document.v1.json` として残し、`source/` と `assets/` のファイルは動かさない(パスはデータに書いてあるものを使う)。

### 5.2 ドキュメントモデル
ページごとにレイヤーとオブジェクトを持つ。オブジェクトは共通属性(安定ID、種別、変換行列、Z順、タグ、メタデータ)を持つ。
- Path: 頂点列(ベジェ含む)、塗り、線色、線幅、閉/開
- Text: 文字列、フォント、サイズ、字間、色、配置、任意で「輪郭Pathで描画」フラグ
- Image: アセット参照、変換
- 役割(role): 枠 / ラベル / 記入マス / 項目コードの印字 / QR / 様式ID など
- 項目コード(fieldCode): 例 G01。二次利用(データ流し込み、AcroForm化)の鍵になる

レイヤー構成:
1. 背景ラスター(ロック)
2. 自動抽出の候補(未確定)
3. 確定オブジェクト(出力対象)
4. 差分オーバーレイ(確認用)

自動抽出は「候補を出すだけ」にして、人が確定した時点でレイヤー3に入る。精度が低くても使える設計にする。

### 5.3 パイプライン
取り込み(背景ラスター抽出) → 候補抽出(Vectorizer / OCR) → 人手調整 → 確定 → 出力(PDF / SVG / JSON) → 自動検証

自動検証: 出力PDFをラスタライズして背景との差分を計算し、PoCの成功基準を数値化する。

### 5.4 Electron 構成
- main: ファイルI/O、PDF抽出・出力、重い処理(ベクタライズ、OCR)を utility process で実行
- renderer: React + SVG。ドキュメントモデルを正とし、保存時にmainへ渡す
- 座標系: 内部はPDF座標(ポイント、左下原点)のまま保持し、SVG座標への変換レイヤーを1枚挟む
- Undo/Redo(コマンドパターン)は最初から入れる
- 参考: Inkscape(ビューと操作感)、stablyai/orca(Electron構成)

## 6. Text の方針
- 実フォントのTextとして出力する(コピー・検索・再利用可能)。
- 文字内容は人が確定する。OCR(Tesseract、macOS Vision 等)は候補提示のみ。
- 元フォントは Meiryo(サブセット埋め込み。画像PDFなので実際には画像化されている)で、再配布できない。出力は Noto Sans JP 等の再配布可能なフォントで近似し、PDFに埋め込む。
- 編集機能: フォントファミリ変更、サイズ変更、位置、字間。見た目の再現用に「輪郭Pathで描画」への切替も用意する。
- 出力側は PDFKit で日本語フォントをサブセット埋め込みする(§3-28。pdf-lib + fontkit は検証の結果、採らない)。

## 7. PoC スコープ(案)
1. 第一表(2ページ目)を300dpiで背景ラスターとして取り込む
2. 罫線・枠を検出して Path 候補にする(水平・垂直に正規化)
3. ラスター上に重ねて表示(不透明度、差分表示)。ノード・線分の選択とキー操作での微調整
4. ラベル文字を Text オブジェクト化(OCR候補 + 手動確定)、フォント・サイズ編集
5. 項目コードのタグ付け
6. PDF / SVG / JSON 出力と、背景との自動差分検証

成功基準(初期): 差分が目視で気にならない。その後、画素差分率などで数値化する。
